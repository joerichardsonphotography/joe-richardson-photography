# Joe Richardson — photography portfolio (Prismic template)

A wedding + editorial photography portfolio built with Next.js (App Router)
and Prismic. Homepage is a looping, hover-previewed project list; each
project opens into an asymmetric masonry gallery.

This is an **original build inspired by the layout pattern** of full-bleed
typographic photography portfolios — no code, copy, or assets were copied
from any existing photographer's site. All content is driven by Prismic, so
you can fully re-brand, re-copy, and re-image it without touching code.

## What's inside

- **Custom types** (`/customtypes`)
  - `homepage` — a single slice-zone page, currently only accepting the `ProjectGrid` slice.
  - `project` — repeatable. Fields: `name`, `category` (Wedding/Editorial), `couple_name`, `wedding_date`, `location`, `info` (rich text — overrides the couple/date/location block when filled, for editorial work that doesn't fit the wedding shape), `cover_image`, `gallery` (repeatable image group), `sort_order`, plus SEO fields.
  - `settings` — singleton. Site title, default meta description, a signature/wordmark image for the fixed corner mark, email, Instagram link.
  - `about` — singleton. Portrait image + rich-text bio (multi-paragraph).
  - `contact` — singleton. Optional intro rich text; the actual email/Instagram shown on the page are pulled from `settings` so they only need to be entered once.

- **Slice** (`/src/slices/ProjectGrid`)
  - Server component fetches all `project` documents (ordered by `sort_order`, then publish date) and passes them to a client component that owns the interactive bits.
  - `useInfiniteScrollLoop` — renders the project list five times stacked and silently teleports scroll position back to the middle band near either edge, so the list feels endless. No dependency on any external animation library.
  - `useActiveProjectLink` — on desktop, tracks real cursor position (re-resolved on scroll) to know which project link is "under" the pointer even while the page scrolls; on touch devices, samples a fixed reading line instead, since there's no persistent hover state.
  - A single brick-red (`#B5241C`) index numeral is the one accent color in the whole design, appearing only next to the active preview thumbnail.

- **Project detail page** (`/src/app/project/[uid]`) + **`ProjectGallery`** component
  - Three unequal columns (not a plain grid) with deterministic per-image offsets, so every gallery feels hand-arranged rather than templated, without layout shift between renders.
  - Landscape images auto-detect on load and scale up slightly to balance the visual weight against portrait crops, matching editorial-magazine pacing.
  - The `info` rich text field (if filled) replaces the couple/date/location block entirely — use this for non-wedding editorial projects.

- **Root layout** — Archivo Black for display type, Inter for body/meta text; a fixed bottom-right signature mark on every page (falls back to "JR" text if no image is set in Settings); a quiet top-right About/Contact nav; reduced-motion support; hidden scrollbar (required so the scroll-loop teleport is never visible as a scrollbar jump).

- **About page** (`/about`) and **Contact page** (`/contact`) — both driven by their own singleton documents. Contact intentionally has no form; it shows the email and Instagram link already entered in `settings`, so there's only one place to update contact details. If you want a real form later, the cleanest options are embedding a third-party form service (Formspree, Tally, your booking tool's embed) or a small serverless route — ask and it can be added.

## Getting started

1. **Install dependencies**

   ```bash
   npm install
   ```

2. **Create a Prismic repository** at [prismic.io](https://prismic.io) (Next.js / App Router template, or start blank — the custom types here will replace whatever's scaffolded).

3. **Set your repository name**

   Copy `.env.local.example` to `.env.local` and set it to your repo's slug (the part before `.prismic.io` in your repo URL):

   ```bash
   cp .env.local.example .env.local
   ```

   ```
   NEXT_PUBLIC_PRISMIC_ENVIRONMENT=your-repo-name
   ```

   Also update `slicemachine.config.json`'s `apiEndpoint` to match.

4. **Push the custom types and slice with Slice Machine**

   ```bash
   npm run slicemachine
   ```

   Open the local Slice Machine UI it prints (usually `http://localhost:9999`), and push:
   - the `homepage`, `project`, `settings`, `about`, and `contact` custom types
   - the `ProjectGrid` slice

   > Note: `prismicio-types.d.ts` in the project root is currently **hand-written** to match these custom types exactly, since it's normally auto-generated by Slice Machine against a live repo. Once you push and Slice Machine regenerates this file for real, let it overwrite — the shape should already match, so nothing else needs to change.

5. **Add content in Prismic**
   - Create the `Settings` singleton document (site title, signature mark image, contact email, Instagram).
   - Create the `Homepage` document, add a `ProjectGrid` slice to its slice zone, and publish.
   - Create the `About` singleton document (bio paragraphs, optional portrait photo), and publish.
   - Create the `Contact` singleton document (optional intro text — email/Instagram come from Settings), and publish.
   - Create a few `Project` documents — set a `name`, `sort_order`, `cover_image`, and a `gallery` of images. For weddings, fill `couple_name` / `wedding_date` / `location`. For editorial work, fill `info` instead (it takes priority when present).

6. **Run locally**

   ```bash
   npm run dev
   ```

   Visit `http://localhost:3000`.

## Deploying

Deploys cleanly to Vercel (recommended) or any Next.js host. Set the same
`NEXT_PUBLIC_PRISMIC_ENVIRONMENT` environment variable there. Add your
production domain to your Prismic repo's CORS/preview settings if you enable
live previews.

## Notes on customizing further

- **Colors / type** live as CSS variables in `src/app/globals.css` (`--ink`,
  `--paper`, `--accent`, `--muted`) and as font variables wired in
  `src/app/layout.tsx` — swap the Google Fonts imports there for anything
  else without touching component code.
- **Category filtering** (Wedding vs Editorial) isn't wired into the UI yet —
  the `category` field exists on `Project` so it's ready for a filter control
  if you want one added later.
- **Repeat count** for the infinite scroll loop (currently 5 stacked copies)
  is a constant (`REPEAT_COUNT`) at the top of `ProjectGridClient.tsx`.
